# 10 条曲线 × 每条 1000 点/秒：自建缓冲写法 vs 控件多曲线 API

- 生成时间：2026-10-12 15:05:29
- 操作系统：Microsoft Windows 10.0.26300；处理器：Intel64 Family 6 Model 198 Stepping 2, GenuineIntel（逻辑核心数 24）
- 控件 1100×660，普通不透明窗口；每条曲线显示最近 60 秒；开始前先给每条曲线灌满一个窗口（60,000 点），测的是长时间运行后的稳定状态
- 每种写法预热 2 秒后测量 8 秒
- 构建配置：Release（Debug 构建下控件代码不经 JIT 优化，而 ScottPlot 来自 Release 包，两种写法不可比，请用 Release 运行）
- 各写法交替执行 2 轮：UI 线程 CPU 取较小值，其余取均值
- CPU 计量为周期精确（QueryThreadCycleTime / QueryProcessCycleTime，按忙等校准换算成时间），不受 15.6 ms 时钟采样记账的影响
- **UI 线程 CPU**：UI 线程自身的 CPU 时间（GetThreadTimes），即“接收数据 + 计算坐标轴 + 绘制”的全部开销，是比较两种写法的主要指标；
  进程 CPU 还包括 10 个采集线程（每毫秒唤醒一次）与 GC / JIT 后台线程，波动大，仅供参考
- UI 延迟：后台线程每 5 ms 投递一次 BeginInvoke，到 UI 线程执行的耗时

|---|---|---|---|---|---|---|---|---|
| A1 自建缓冲 + 原生 Signal（旧演示写法） | WinForms 定时器 33 ms | 10,003 | 21.4 | **13.8%** | **6.48** | 19% | 0.1 / 1.4 / 6 | 600,000 |
| A2 自建缓冲 + 原生 Signal（旧演示写法） | WinForms 定时器 16 ms | 10,001 | 39.8 | **28.3%** | **7.11** | 29% | 0.2 / 1.0 / 8 | 600,000 |
| B 控件多曲线 API（采集线程直接 AddValues） | MaxFramesPerSecond = 30 | 10,004 | 29.6 | **16.8%** | **5.68** | 19% | 0.4 / 3.5 / 6 | 700,187 |
| C 控件多曲线 API（采集线程直接 AddValues） | 不限帧率 | 10,007 | 72.2 | **29.9%** | **4.15** | 32% | 0.3 / 1.0 / 5 | 700,250 |
| D 控件多曲线 API + 相对时间单位 | 不限帧率 | 10,003 | 68.2 | **26.4%** | **3.87** | 30% | 0.2 / 0.7 / 4 | 700,240 |

说明：
- A1 是旧演示的默认设置：33 ms 的 WinForms 定时器受系统时钟约 15.6 ms 精度影响，实际约 47 ms 一帧（约 21 FPS）；
  A2 把定时器设为 16 ms（实际帧率取决于系统时钟精度），用来和 B 在相近帧率下比较。
- B / C 由控件按帧合并跨线程写入，B 的帧率上限由高精度定时器控制；C 不限帧率，每帧画完立即处理下一批数据。
- D 与 C 相同，只是 X 轴单位为相对时间（每条曲线按采样率换算成秒、跟随窗口 60 秒、时间刻度生成器），用来确认时间单位没有额外开销。
- 自建缓冲写法只保留最近 60 秒（内存恒定）；控件目前保留全部历史数据，内存中点数随运行时间增长（每条每小时约 360 万点、约 32 MB）。
