## 结论

### 最大每秒数据更新数量

| 使用方式 | 最大更新率 | 说明 |
|---|---|---|
| 仅数据接入（堆叠模式，合并渲染） | **≈ 1,020,566 点/秒** | O(1)/点，与缓冲区大小无关 |
| 仅数据接入（堆叠模式显示 90% / 拖动后继续滚动，100 万点） | **≈ 886,998 点/秒** | 可见范围查询走极值金字塔，与窗口长度无关 |
| 仅数据接入（跟随模式） | **≈ 952,422 ~ 863,595 点/秒** | 可见范围查询走极值金字塔，与窗口长度无关 |
| 数据 + 真实绘制交错（堆叠 1,000 点） | **≈ 849 点/秒** | 绘制成为瓶颈 |
| 数据 + 真实绘制交错（堆叠 10,000 点） | **≈ 788 点/秒** | 屏上点数越多越慢 |
| 数据 + 真实绘制交错（堆叠 100,000 点） | **≈ 701 点/秒** | |
| 每个点后立即绘制一帧（1,000 / 10,000 / 100,000 点） | **≈ 636 / 637 / 338 点/秒** | 最保守用法 |

### 工程结论

- 数据接入本身很快：堆叠模式约 **1,020,566 点/秒**（0.98 µs/点），各场景最低也在 **863,595 点/秒** 以上（可见范围 Y 轴统计不再随窗口长度变慢）。
- 单帧绘制（1100×660）：空图 1.43 ms，10,000 点 2.23 ms，300,000 点 3.85 ms，1,000,000 点 3.78 ms，基本不随点数增长（极值金字塔 + 自绘画布）。
- 大窗口（1920×1080）：空图 2.79 ms，300,000 点 10.40 ms（≈ 96 FPS），1,000,000 点 9.69 ms；呈现开销随像素面积增长。
- 按 60 FPS（16.7 ms/帧）规划时，屏上点数建议控制在约 1,000,000 点以内；本例 10,000 点为 449 FPS。
- 每秒 1 点（本控件默认使用场景）或每秒几十~几百点的采集卡场景：余量在百倍以上，无压力。
- 每秒上万点的场景：建议灌入照常（不丢点），同时限制屏上点数（例如滚动缓冲、抽稀显示）以获得稳定的刷新率。
